## 🔧 Improvements

- Separated create, update, and delete permissions
- Explicitly allows users to create their own user document
- Enhanced login_logs rules to handle failed login attempts

## 📝 Commit Message

```
fix: Resolve Google authentication Firestore write failures

Fixed multiple issues preventing Google authentication from writing to Firestore:

1. Auth Manager: Changed lastSeenAt update from .update() to .set() with merge
   - Prevents errors when user document doesn't exist yet
   - Uses merge:true to safely update existing documents

2. Firestore Rules: Made user creation rules more explicit
   - Separated create, update, and delete permissions
   - Explicitly allows users to create their own user document
   - Enhanced login_logs rules to handle failed login attempts

3. Error Handling: Added comprehensive Firestore error handling
   - Wraps Firestore writes in try-catch blocks
   - Logs detailed permission-denied errors
   - Continues authentication flow even if Firestore writes fail
   - Applied to Google, Facebook, and Apple sign-in methods

4. Firebase Configuration: Added deployment setup
   - Created firebase.json for Firebase CLI
   - Created .firebaserc with project configuration
   - Created firestore.indexes.json for query optimization
   - Added DEPLOY_FIRESTORE_RULES.md with deployment instructions

The authentication now works properly with Firestore database writes.
Users need to deploy the updated Firestore rules using Firebase CLI.

Fixes issue where Google sign-in appeared to work but didn't write to Firestore.
```
